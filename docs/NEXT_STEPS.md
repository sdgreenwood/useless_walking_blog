# Next steps after launchable V1

These are intentionally outside the launch tranche:

1. Add visual route-crop tooling instead of meter-only endpoint trimming.
2. Add richer climb phases, stopped-time detection, and cumulative gain per replay sample.
3. Replace the public tile style with a service-level-backed provider if traffic justifies it.
4. Add screenshot/social-card generation for replay links.
5. Add an authenticated private administration UI only if command-line publishing becomes burdensome.
6. Consider object storage or a database only when publishing through the deployed app becomes a real requirement.
7. Add historical comparisons only after multiple curated routes share a stable analysis version.

Public uploads, accounts, payments, social feeds, live GPS, HealthKit access in the web app, route recommendations, and native apps remain out of scope.
